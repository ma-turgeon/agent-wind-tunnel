Read this before interpreting the results

Limitations are part of the architecture.

The project is designed to make implementation behavior inspectable. Its current evidence does not establish production safety, semantic superiority, savings, or ROI.

Evidence

  • Built-in and enterprise cases are fictional synthetic composites.
  • The fixture ladder is intentionally calibrated and deterministic.
  • The project controls the built-in tasks, checks, implementation, expected behavior, and documentation.
  • No independent semantic grader is bundled.
  • The separated composite file is not production data, external validation, or a statistically representative benchmark.
  • The optional human-review kit has no completed review sheets, calibrated labels, or measured inter-rater agreement.
  • The six-run live pilot confirms bounded execution and records one narrow comparison; it does not establish independent semantic correctness or general topology advantage.

Architecture

  • Only four canonical behavior families and checked-in ablations are accepted.
  • The Graph Max derivation is a bounded source-pattern scan, not a general parser.
  • Structural complexity uses declared weights and is only a post-gate tie-breaker.
  • One live provider adapter is included.
  • The harness is not a high-throughput serving platform.

Security

  • The local broker is not IAM, a sandbox, or a production approval system.
  • The fixture approver is not authenticated human approval.
  • The effect is a data-only simulation and never deploys.
  • There is no tenant isolation, arbitrary tool sandbox, distributed idempotency, or signed audit trail.
  • Approval dominance proves graph structure—not approver identity, intent, or decision quality.

Cost

  • Fixture cost units and latency ticks are synthetic.
  • A live Price Card is a versioned operator-supplied estimate input.
  • Conservative spend envelopes price declared token budgets and are not billing guarantees.
  • Realized estimates are not provider invoices and require recomputation when prices, routing, tier, region, or tools change.

No production outcome claim

The repository contains no production adoption, throughput, incident, revenue, savings, or ROI measurement. A recommendation is conditional on the selected tasks, candidates, model, prompts, tools, policy, graders, budgets, Price Card, and complexity definition.

What stronger evidence requires

  1. Independently owned, representative held-out tasks.
  2. Predeclared hypotheses and stopping rules.
  3. Paired repeated live trials.
  4. Executable domain checks and blinded human labels.
  5. Model graders calibrated against those labels.
  6. Uncertainty, failure distributions, and sensitivity analysis.
  7. Independent reproduction.
  8. Real platform controls and measured operational outcomes.
